# 技术点快搜产品需求文档

> 2026-10-22用户决定：取消自动/手动Fetch与内置正文阅读，详情交给默认浏览器；本文件为当前范围。[变更前完整PRD](archive/PRD-before-search-only-2026-10-22.md)保留追溯，旧正文成功率、正文缓存/查找/复制和Fetch增量价值不再是新版交付门槛。已接受本机明文Key保存及简洁首页要求一并对齐；其他未冲突需求继续保留。


产品暂定名：技术点快搜。版本：0.1 内测版。更新日期：2026-10-22（Search-only变更）。

**产品承诺：复制一个技术点，按快捷键，快速找到值得看的相关专利和技术资料。** 用户可以在阅读、撰写专利的过程中随时调用，查看检索摘要并在浏览器打开来源，再回到原来的工作。

核心能力由 DeepSeek Search 提供：Search发现公开资料，详情由默认浏览器承接。本版重点验证高频使用和检索价值，尚未实现的能力不得展示为可用功能。

第一期采用 **Tauri 2** 开发，同时交付 Windows 和 macOS 桌面应用。用户填写自己的 DeepSeek API Key 即可使用，并可在应用中查看该密钥所属账户的余额；本版不提供支付、充值或订阅功能。

本文件是 0.1 版本的开发基准；其他研究文档用于解释产品假设。验收时同时使用 [验收清单](./acceptance-checklist.md)。

## 1 产品目标与边界

| 目标 | 具体要求 |
|---|---|
| 容易理解 | 首次打开即可看到一句话用途、输入框、搜索按钮和一条公开技术主题示例 |
| 低成本进入工作 | 配置完成后，快捷键唤起即可粘贴并搜索，无需创建项目或上传文件 |
| 高频短任务 | 首批结果先显示，后续Search候选追加；用户随时可以打开来源、改词或收起窗口 |
| 主要价值来自检索与来源发现 | 首版不依赖另一个生成模型、专业数据库或本地文件分析才能完成主流程 |
| 值得继续阅读 | 返回可打开的来源，摘要只标为搜索返回内容，详情跳转原网页 |

本版用于发现相关公开资料，不提供“没有相似专利”“具备新颖性”“不会侵权”等判断。结果列表是本轮候选集，不代表专利数据库的完整覆盖。界面以“相关资料”“检索结果”描述输出。

高频使用、实际省时和检索效果是待验证假设。延迟与质量指标是开发及内测目标，不是已测得的数据或对外服务承诺。

## 2 用户与使用任务

首版使用一个产品、同一套界面，不设置“审查员版”和“代理师版”，也不要求选择职业才能搜索。

| 用户 | 触发场景 | 期望完成的任务 |
|---|---|---|
| 专利审查员 | 阅读申请文件，遇到一个技术特征或部件关系 | 查找类似技术做法的公开资料，打开原文核查 |
| 专利代理师 | 阅读交底材料、撰写申请或分析对比文件 | 找到相关技术表述和参考资料，继续自己的工作 |

初期招募两类用户观察差异。若审查员的单位不允许安装或使用外部服务，不将其纳入该环境的试点，也不因此要求首版支持机构私有部署。

典型任务：用户复制公开技术描述“通过弹性件补偿夹爪磨损，保持夹持力稳定”，唤起窗口并提交，阅读摘要并在浏览器查看原网页，选择有用来源后回到工作文档。该描述用于交互示例，不对应预设真实检索结果。

## 5 页面与核心操作

### 5.1 首次打开与服务配置

未配置密钥时仍显示产品用途和输入示例，主操作为“填写 DeepSeek API Key”。点击后进入“设置 → 检索服务”，配置前已输入的检索词保留。该设置入口始终可从主窗口进入，用户无需命令行或修改配置文件。

| 设置项 | 交互要求 |
|---|---|
| 字段名称 | DeepSeek API Key |
| 输入提示 | 粘贴你自己的 DeepSeek API Key |
| 输入方式 | 支持输入和粘贴，默认遮挡；正在填写的新密钥可切换显示/隐藏 |
| 保存并返回 | 非空且通过基础检查后按用户确认保存至本机用户配置，返回原搜索界面；不自动搜索 |
| 已配置状态 | 只显示“已配置”及可选的末尾 4 位，不把完整已保存密钥回填到界面 |
| 更换密钥 | 打开新的空输入框；取消编辑不改变原密钥 |
| 删除密钥 | 清除本应用本地配置及内存中的Key，停止当前任务并回到未配置状态；保留本地历史 |
| 费用说明 | 检索使用你自己的 DeepSeek 账户额度，费用由 DeepSeek 收取；本产品第一期不提供支付、充值或订阅功能 |

保存时去掉首尾空白，拒绝空值及含内部空白或控制字符的输入；不假设密钥必须具备固定前缀或固定长度。取消或保存失败时保持原配置，原子写入失败保留原文件与原配置。保存失败提示“无法安全保存密钥，请重试”，保留本次输入供用户处理；关闭设置时清除未保存的密钥草稿。空输入不能代替删除操作。

“保存”只做本地格式基础检查，不发送任何网络请求，也不提示“鉴权成功”。搜索成功与余额查询成功分别记录连接状态，不用余额查询成功推断 Search 可用。成功更换密钥时停止旧任务和余额请求，使旧响应失效，并清除旧密钥的连接状态及余额快照；新密钥保存后等待用户主动搜索或查看余额。首次提交搜索前展示一次服务说明并由用户确认启用：查询文字会发送给DeepSeek，费用由其 API 账户承担。更换密钥不反复展示同一份说明。

配置及搜索入口附近提示“请仅输入可发送至外部服务的内容”。首批内测使用公开资料；软件不自动判断内容是否保密。帮助中的控制台和文档链接须在发布前验证目标地址。

### 5.2 主窗口

窗口包含产品名、输入框、范围选择、搜索/停止按钮，以及历史和设置入口。初始说明为“复制一个技术点，查相关专利和技术资料”。

Windows 默认唤起快捷键为 `Ctrl+Alt+Space`，macOS 为 `Option+Command+Space`，均允许修改。注册失败时保留系统托盘或菜单栏入口，提示“无法注册快捷键，请检查系统设置或换一个组合”，不能静默覆盖系统或其他软件快捷键。用户主动点击唤起后，将焦点放入输入框；不得全局劫持普通输入。

快捷键在窗口隐藏时显示，在已显示且聚焦时收起。`Esc`先收起余额、历史返回设置、设置返回搜索，最后静默收起主窗口。点击窗口外部不自动关闭；用户可切换到编辑器，搜索状态仍保留。

Windows 点击关闭按钮或按 `Alt+F4` 收起到系统托盘；macOS 点击红色关闭按钮或按 `Command+W` 收起窗口，菜单栏入口仍可用。收起不显示弹窗或通知。Windows 托盘菜单、macOS 菜单栏菜单均提供“退出”；macOS 应用菜单“退出”及 `Command+Q` 真正结束应用。退出时取消全部未完成请求，包括余额查询。重新启动不自动恢复联网任务。

唤起和收起不读取剪贴板、不发送请求、不自动覆盖输入。输入粘贴、复制和全选遵循系统习惯：Windows 使用 Ctrl，macOS 使用 Command。中文输入法与键盘导航需在两个系统分别验收。

### 5.3 输入与提交

输入支持中文、英文、数字、引号和关键词组合。界面显示字符计数。换行转换为空格并移除首尾空白，内部文字不自动改写；保存规范化后的内容作为本轮输入。

规范化后为空或超过 100 个 Unicode 字符时禁止提交，保留全部输入并就地解释，不自动截断。长度按 Unicode 码点计数，避免中英文或非 BMP 字符在不同端计数不一致。

用户可直接输入官方高级语法：`site:`、`-site:`、`lang:`、`after:`、`before:`、英文双引号精确短语、排除词/短语及多站点大写`OR`。不提供筛选面板；搜索框旁问号按需展示可复制示例、限制及站点优先规则，Escape或点击外部关闭并聚焦搜索。日期指网页发布时间，不是专利优先权日。操作符、短语与OR不改写、不转义为普通文字。

非输入法组词状态下按 Enter 提交；中文输入法确认候选词时不得提交搜索。输入错误不会清空上轮结果。

检索中修改输入只改变草稿，不改变在途任务。结果区域持续显示实际正在检索的词。提交新输入或新范围时取消旧任务并创建新任务；相同输入和范围在任务运行期间重复提交，不增加请求。任务结束后的再次提交明确视为重新搜索，可产生新费用。

### 5.4 结果与来源

卡片展示Search实际返回的标题、摘要、来源域名及从URL识别的公开号。snippet优先、summary可作缺省摘要，不生成额外总结，不标为网页正文或已核实的专利信息。返回顺序稳定，新候选追加，接近底部时自动按5条渐进显示已接收结果。

点击标题、“打开原网页”或选中结果后Enter，使用系统默认浏览器打开该候选首次保留的原始URL。HTTP/HTTPS、host、无用户名密码、无控制字符、最长8192字符须在前后端校验；校验不重写原URL，不丢查询参数、编码、大小写或fragment。不得执行脚本、本地文件、data等协议，不绕过登录、访问限制或浏览器安全提示。网页可达性由来源网站和浏览器决定。

复制来源保留标题、可识别公开号和原始URL。没有内置阅读器、正文预览/查找/选区复制、抓取状态、正文错误、手动抓取或正文重试。所有打开/复制/展开已有结果操作均不产生Search或Fetch请求。

### 5.5 继续查找

接近列表底部160px时自动显示下一批5条已接收结果，不增加API请求；保留可键盘操作的“显示更多结果”作为兼容备用。重复触发只显示一批，结束后标为“本次结果已全部显示”；提交新查询或恢复历史复位并使旧回调失效。本地渲染调度异常保留已显示内容，可手动重试。更改草稿或范围不影响当前列表；主动提交才创建新任务。已结束任务再次提交同词属于新任务；运行中的相同任务不重复提交。

### 5.6 DeepSeek 账户余额

入口为“设置 → 检索服务 → 查看账户余额”。未配置密钥时提供填写入口，不发请求。入口旁说明“查询当前 API Key 所属的 DeepSeek 账户余额”。点击查看即使用已保存密钥向 DeepSeek 查询，不发送检索词、正文或本地历史，也不需要创建本产品账号。

| 展示项 | 规则 |
|---|---|
| 可用总余额 | 直接展示接口的 total_balance，包含赠金和充值余额，不与明细重复累加 |
| 余额明细 | 展示 granted_balance 为“赠金余额”、topped_up_balance 为“充值余额” |
| 币种 | 按 currency 分组显示，明确标注 CNY 或 USD；不合并不同币种，不做汇率换算 |
| 账户可用状态 | is_available 为 false 时提示“账户当前无可用余额”；为 true 只代表余额接口报告可用，不保证检索请求一定成功 |
| 更新时间 | 显示最近成功查询的本地时间；保留提示“余额可能因其他应用调用而变化，点击刷新查看” |
| 刷新 | 用户主动获取最新余额；请求中显示“正在查询余额”，按钮禁用且重复点击合并 |

首次点击“查看账户余额”且本次启动尚无成功快照时发起查询；已有快照时展示缓存和更新时间，点击“刷新”才再次请求。启动、保存密钥、唤起主窗口、打开设置或完成搜索都不自动查询余额，不做后台轮询。关闭余额面板不会重新发请求；已有请求可完成并更新本次会话的缓存。

余额请求单独管理，不占用单轮 Search 的 4 次尝试预算。余额模块最多一个在途请求，单次超时 10 秒，不自动重试；与 Search 的最多两个并发请求分别计数，因此应用最多同时存在三个 API 请求。余额查询或失败不阻塞搜索、打开来源及取消操作。429 时遵守 Retry-After，倒计时结束后才允许手动刷新；没有该字段时默认等待 30 秒，不自动发出请求。

| 状态 | 界面与恢复动作 |
|---|---|
| 查询中且无快照 | 显示“正在查询余额”，金额位置不填 0 |
| 查询成功 | 展示余额、明细、可用状态和更新时间；真实零值按返回结果展示 |
| 网络失败或超时 | 无快照时显示“暂时无法查询余额，请重试”；有快照时保留旧值并标明“刷新失败，以下为上次查询结果” |
| 401 | 显示“API Key 无效，请在设置中更新”；旧快照不再作为当前余额展示，提供更换密钥入口 |
| 429、其他服务错误或响应不合规 | 显示对应查询失败状态，可用旧快照必须标明非最新；不把失败、空数组或缺失字段解释为零余额 |

金额以十进制字符串校验与保存，避免二进制浮点计算或展示造成精度变化；收到不支持的币种或无法解析的金额时标记响应不合规。余额是整个 DeepSeek 账户的快照，不是本产品专属额度，不用两次余额差值计算本次检索费用。余额为零或 is_available 为 false 时不直接禁止用户搜索，实际搜索响应决定是否停止本轮；避免旧余额阻止账户恢复后的正常使用。

更换或删除密钥时立即清空余额及时间，取消旧请求；迟到响应不得恢复旧账户余额。第一期仅查询和展示余额，不提供充值入口、支付流程、账单、消费流水、套餐或订阅。

## 6 检索与请求规则

### 6.1 查询计划

设规范化后的输入为 Q。首版不自动拆技术特征、翻译、补同义词或改变用户的必要限定。

| 范围 | 查询计划 | UI 说明 |
|---|---|---|
| 专利与技术资料 | Q 加 `site:patents.google.com`；Q 原样通用网页查询；两条可并发 | 包含专利定向检索及通用网页检索，资料类型和完整性需核查 |
| 仅专利 | Q 加 `site:patents.google.com` | 当前定向来源为 Google Patents，不代表全量专利库 |

每条Search请求最多返回50条结果，`need_content=false`；`ori_question` 使用 Q，不设置定位 IP。生成后的 query 必须再次检查官方长度限制。若内部生成不合法，阻止发送并记录可诊断错误，不静默丢词。

若查询在英文双引号外含显式`site:`或`-site:`，以用户站点条件为准：仅发送规范化后的原查询一次，不附加Google Patents条件，也不强制过滤为专利路径。范围位置显示“按查询中的站点条件”，删除该条件后恢复用户先前选择的范围；引号内的`site:`文字不触发覆盖。没有显式站点时，“仅专利”模式只展示识别为 Google Patents 专利文档路径的候选；站点主页、搜索列表等不混入候选结果。混合模式允许一般网页资料；通用检索中识别出的专利页同样可以展示。

### 6.2 合并与稳定展示

首个响应按其返回顺序建立卡片；之后的响应按返回顺序追加未出现的候选。不把不同查询的分数当作已校准分数做全局比较。用户正在查看的卡片不能因新响应到达而跳动、失焦或消失。

同一 Google Patents 公开号的不同语言页面合并，保留每个命中 URL 和查询来源，使用首次显示的原始URL打开浏览器。文献种类代码属于身份的一部分，A1、B2 等不同版本不得合并，也不做专利同族合并。

其他网页按规范化 URL 去重：域名大小写及默认端口归一，忽略片段标识；保留路径及查询参数，不任意删除参数导致不同页面误合并。原始 URL 始终保留用于打开来源。无法确定是否相同的资料宁可分别显示。

当前公开Search schema无page/offset/cursor或后页标记，未知参数被忽略。这里是已有结果的渐进显示，不是服务端分页：仅专利一请求最多50，混合两请求合计最多100、去重后可更少；不改写查询、日期分片或造游标获取所谓下一页。不承诺取得该有限结果池之外的候选。

### 6.3 禁止正文抓取

不执行任何自动或手动Fetch请求，不接受前端以fetch操作调用Rust传输接口，不通过Search的need_content取得正文（固定false）。不对来源网页发应用内请求，不另行总结。详情仅交给默认浏览器，浏览器按用户点击请求公开来源。

### 6.4 任务时限与请求预算

| 项目 | 上限 |
|---|---|
| 任务总时限 | 60秒 |
| 逻辑Search | 混合最多2条，仅专利1条，每条count=50、need_content=false |
| 检索并发 | 最多2个Search |
| 自动重试 | 暂时网络故障、408、429、5xx最多一次，遵守Retry-After，等待及15秒请求余量必须能放进剩余时限 |
| 网络尝试总数 | 混合最多4次、仅专利最多2次，包含重试；Fetch固定0 |

截止、取消、替换、删除或退出立即停止排队与重试，旧响应不得更新新任务。401/402终止当前检索；其他永久4xx不自动重试。取消不能保证撤销服务端已经处理的请求或计费。余额独立最多1在途、10秒、无重试，不占Search预算；不计算余额差值费用。实际Search费用以服务账单为准，主流程不反复弹费用提示。

## 7 状态与中断行为

状态包括：searching、complete、partial（部分Search失败但有结果）、empty（全部成功但无结果）、failed、stopped、expired。没有reading/抓取阶段。快Search结果先显示，不等第二个Search；完成后可以直接打开或复制来源。

每次提交产生新run_id。停止、替换、删除历史和退出使旧响应失效。隐藏窗口不取消当前Search，也不抢焦点或弹通知；重新唤起保留输入、范围和已显示结果。恢复历史不联网、不恢复请求预算；曾在Search进行中的历史显示为已停止。旧reading或仅正文失败的partial记录按已有Search完成情况投影展示，不继续抓取。

首页仅一个轻量设置入口。历史/Key/余额/快捷键/本地管理位于设置；历史为设置子页，Escape回设置并聚焦历史入口，关闭设置回搜索。Escape、Command+W、系统关闭静默隐藏；首次也没有说明弹窗。托盘/菜单栏退出或Command+Q真正退出并取消请求。

## 8 异常与界面文案

| 情况 | 用户文案 | 行为 |
|---|---|---|
| 空输入 | 请输入一个技术点或公开号 | 不发请求 |
| 输入过长 | 最多输入 100 个字符，请缩短描述 | 保留输入，不截断 |
| 未配置 | 配置 DeepSeek API Key 后即可搜索 | 打开设置 |
| 401 | 检索服务密钥无效，请在设置中更新 | 不重试，停止本轮剩余联网操作 |
| 402 | DeepSeek 账户余额不足，可查看账户余额 | 不重试，停止本轮剩余检索操作；提供余额面板入口，用户点击后才查询 |
| 429 | 检索服务繁忙，正在稍后重试 | 按退避和时间预算处理；结束后允许主动重新搜索 |
| 网络或服务暂时失败 | 暂时无法完成检索，已保留返回的结果 | 有限重试，结束后保留数据 |
| 混合模式部分 Search 失败 | 部分来源未完成，以下为已返回结果 | 不显示成完整范围检索成功 |
| 全部 Search 成功但无候选 | 本轮未找到相关资料，试试修改关键词或扩大范围 | 不表示相关技术不存在 |
| 用户停止 | 已停止，已返回的结果仍可查看 | 停止后续任务 |
| 总时限到达 | 本轮已结束，已保留返回的结果 | 停止后续任务，允许重新搜索 |

对于其他不可重试请求错误、协议不符及本地失败，主界面提供简短说明和可恢复动作；诊断页记录错误类别、状态码及请求时间，不直接展示可能包含密钥或查询内容的服务端原始错误。

## 9 结果真实性与内容处理

标题、snippet、summary仅来自Search返回字段，按普通文字安全呈现，不生成新摘要、正文、专利字段、页码或法律状态。非法条目隔离；协议坏、搜索失败和空结果区分。不执行返回文本中的脚本或指令，不自动加载远程图片/iframe/附件。

原始URL与用于去重的规范键分离：同公开号语言页合并时，打开首次保留的URL；不同kind不误合并。打开前后端均校验安全协议，参数以独立进程参数交给默认浏览器，不拼shell命令。单个Search响应上限5MiB，超限作为可理解的Search错误，不伪装为空结果。

## 10 本地数据与设置

用户明确接受Key以明文保存在本机用户级应用配置（仓库外），启动自动加载至内存，Search和余额共用缓存，不访问钥匙串。Unix新文件0600、新私有目录0700，原子替换失败保留旧文件/会话；Windows用户目录ACL需目标系统验收。没有前端完整已保存Key读取命令。旧钥匙串不读取、迁移或删除；新版首次由用户自行填一次。

历史默认本机保存，开关控制新任务持久化；最多50次、保留30天。保存查询、范围、时间、Search结果/摘要/原始URL及任务终态，不产生新正文缓存。旧历史的原有字段仍留在存储记录中，不为升级做批量删除；显示投影不传递/展示旧正文与抓取错误。既有历史数量/时间保留规则不变，恢复历史不联网。

用户主动删除历史或清空时取消相关在途任务，迟到响应不能复活。没有独立正文缓存配置/清理入口。余额快照仅内存，退出清空，不进历史/指标/导出。日志和诊断不记录Key、余额、查询、URL、标题或内容；保留必要次数、状态和耗时。

## 11 数据对象与事件约定

保留schemaVersion=1的SearchRun、SearchHit、AppSettings、BalanceSnapshot以兼容既有历史。SearchRun保存ID、版本、查询/范围/时间/状态、Search完成数、逻辑Search数和尝试数；新数据没有logicalFetch。SearchHit保存ID、原始URL、规范键、标题/来源/公开号、Search摘要、命中来源与时间，没有PageContent。

旧reading、fetchStatus、content、preview、fetchedAt等仅作旧记录兼容：投影时省略抓取字段、按Search结果修正可见状态，不修改调用方原对象或专项迁移删除用户数据。

事件包括run_started、search_batch_received、source_opened、source_copied、query_edited、run_cancelled、run_finished。保留请求级ID、尝试、开始结束/状态，指标不得含秘密或内容。取消旧fetch_started/fetch_completed/result_opened正文事件。余额按request_id和credential_generation隔离，不触发Search或改变检索状态。

## 12 API 对接约束

采用已有核对的官方Search和余额契约：Rust固定POST https://api.deepseek.com/v1/tools/search，query最多128字符、ori_question最多100字符、count=50、need_content=false；解析results标题/URL/摘要。GET https://api.deepseek.com/user/balance使用同一Key，无请求体，余额字段/十进制字符串与5.6节一致。没有Fetch端点或其他网页抓取请求。

前端operation只允许search，Rust独立拒绝fetch/其他操作，且拒绝need_content=true。Bearer只在Rust内存构建，错误不暴露响应原文。Search重试遵守6.4；余额独立10秒且无自动重试。无效URL/缺字段条目隔离，整体结构错误不能伪装为空列表。

既有参考：[Search](https://api-docs.deepseek.com/zh-cn/api/search/)、[使用指南](https://api-docs.deepseek.com/zh-cn/guides/search/)、[余额](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/)。未承诺分页、专业专利字段、已知号精确定位、网页可达或法律状态核实。

## 14 内测指标与验证条件

产品首要验证“用户是否在实际工作中反复主动调用”。初期测试用户不少于 5 人，尽可能包含两类角色，并记录其使用许可与环境。只用公开、允许用于外部检索的任务。

指标默认仅本地统计，不自动上传。用户主动导出的指标包含随机任务 ID、时间、行为计数、耗时、状态和调用次数，不包含查询原文、URL、标题、正文、账户余额、密钥或其可逆标识。用户角色由访谈记录，避免在产品里强制收集身份。

| 指标 | 定义 |
|---|---|
| 活跃使用日 | 当日至少提交一次有效查询，并执行打开来源或复制来源中的任一动作 |
| 重复使用 | 同一用户在多个工作日主动使用；另记录每活跃日不同查询的数量，重复重试不计作不同查询 |
| 有用结果 | 用户人工评价至少一条资料值得进一步阅读；点击仅作为行为代理，不能等同于相关 |
| 任务时间 | 从准备搜索到找到用户认可的资料，与其现有方式用难度相近任务对比 |
| 已取消的正文增量实验 | 用户已取消正文能力，此项不再执行、不作为新版门槛 |
| 单任务成本 | 实际网络尝试、有效返回及成本估算，与用户认可的任务结果一并记录 |

建议继续产品化的条件：五位用户中至少三位在一周内主动使用三天以上；第二周仍有至少三位返回；至少 30 个公开任务中，70% 的任务有一条被评为值得进一步阅读的结果；任务完成时间中位数比现有流程降低 30%。这些是内测决策门槛，不代表召回率或市场证明。

按Search-only流程测量查找与打开来源的实际任务效果；取消正文增量对比，不再为使用接口保留Fetch。

第一期只验证重复使用、检索质量和实际省时，不开发收费页面、套餐、订阅、充值、订单、收银台或试用到期限制，也不以购买产品额度解锁功能。后续商业化另行定义需求。若未形成重复使用，不以增加案件管理、撰写等功能掩盖检索主流程的问题。

### 2026-10-22 结果选择补充

结果正常区域点击仅选择并聚焦，不打开浏览器；标题或“打开原网页”明确打开来源，复制按钮只复制。鼠标/键盘共用单一高亮，上下键从当前行或其按钮继续，可跨已有候选的显示批次并滚动进入视口。查询替换/新选择使旧延迟导航失效；不接管设置、帮助和其他表单控件的方向键，也保留输入框多行编辑、组合键及输入法行为。设置关闭恢复结果上下文；语法帮助关闭返回搜索框。

### 2026-10-22 托盘与按键录制补充

菜单栏使用透明单色搜索图形，macOS template适配明暗，不使用实色占位方块。语法帮助只写通用操作说明及必要限制。全局快捷键为点击/Tab聚焦后录制组合键，平台名称显示；仅修饰键不提交，Esc/失焦取消、显式保存、取消修改、默认草稿、失败保留旧绑定。录制临时停用本应用旧绑定并在结束恢复，保存注册/写入失败须回滚，未编辑不写配置。Mac默认仍⌥⌘空格，提示可能与Finder搜索冲突，不修改系统绑定；实际OS行为单独验收。[本轮证据](shortcut-recorder-update.md)。
