# 技术点快搜产品需求文档

产品暂定名：技术点快搜。版本：0.1 内测版。更新日期：2026-10-21。

**产品承诺：复制一个技术点，按快捷键，快速找到值得看的相关专利和技术资料。** 用户可以在阅读、撰写专利的过程中随时调用，查看检索摘要和抓取正文，再回到原来的工作。

核心能力由 DeepSeek Search / Fetch 提供：Search 发现公开资料，Fetch 减少用户逐个打开网页才能阅读正文的操作。本版重点验证高频使用和检索价值，尚未实现的能力不得展示为可用功能。

第一期采用 **Tauri 2** 开发，同时交付 Windows 和 macOS 桌面应用。用户填写自己的 DeepSeek API Key 即可使用，并可在应用中查看该密钥所属账户的余额；本版不提供支付、充值或订阅功能。

本文件是 0.1 版本的开发基准；其他研究文档用于解释产品假设。验收时同时使用 [验收清单](./acceptance-checklist.md)。

## 1 产品目标与边界

| 目标 | 具体要求 |
|---|---|
| 容易理解 | 首次打开即可看到一句话用途、输入框、搜索按钮和一条公开技术主题示例 |
| 低成本进入工作 | 配置完成后，快捷键唤起即可粘贴并搜索，无需创建项目或上传文件 |
| 高频短任务 | 首批结果先显示，正文陆续补充；用户随时可以打开来源、改词或收起窗口 |
| 主要价值来自检索与抓取 | 首版不依赖另一个生成模型、专业数据库或本地文件分析才能完成主流程 |
| 值得继续阅读 | 返回可打开的来源，明确区分检索摘要与从网页抓取到的原文 |

本版用于发现相关公开资料，不提供“没有相似专利”“具备新颖性”“不会侵权”等判断。结果列表是本轮候选集，不代表专利数据库的完整覆盖。界面以“相关资料”“检索结果”描述输出。

高频使用、实际省时和检索效果是待验证假设。延迟与质量指标是开发及内测目标，不是已测得的数据或对外服务承诺。

## 2 用户与使用任务

首版使用一个产品、同一套界面，不设置“审查员版”和“代理师版”，也不要求选择职业才能搜索。

| 用户 | 触发场景 | 期望完成的任务 |
|---|---|---|
| 专利审查员 | 阅读申请文件，遇到一个技术特征或部件关系 | 查找类似技术做法的公开资料，打开原文核查 |
| 专利代理师 | 阅读交底材料、撰写申请或分析对比文件 | 找到相关技术表述和参考资料，继续自己的工作 |

初期招募两类用户观察差异。若审查员的单位不允许安装或使用外部服务，不将其纳入该环境的试点，也不因此要求首版支持机构私有部署。

典型任务：用户复制公开技术描述“通过弹性件补偿夹爪磨损，保持夹持力稳定”，唤起窗口并提交，阅读几条资料的摘要或正文，选择有用来源后回到工作文档。该描述用于交互示例，不对应预设真实检索结果。

## 5 页面与核心操作

### 5.1 首次打开与服务配置

未配置密钥时仍显示产品用途和输入示例，主操作为“填写 DeepSeek API Key”。点击后进入“设置 → 检索服务”，配置前已输入的检索词保留。该设置入口始终可从主窗口进入，用户无需命令行或修改配置文件。

| 设置项 | 交互要求 |
|---|---|
| 字段名称 | DeepSeek API Key |
| 输入提示 | 粘贴你自己的 DeepSeek API Key |
| 输入方式 | 支持输入和粘贴，默认遮挡；正在填写的新密钥可切换显示/隐藏 |
| 保存并返回 | 非空且通过基础检查后保存至系统凭据存储，返回原搜索界面；不自动搜索 |
| 已配置状态 | 只显示“已配置”及可选的末尾 4 位，不把完整已保存密钥回填到界面 |
| 更换密钥 | 打开新的空输入框；取消编辑不改变原密钥 |
| 删除密钥 | 清除系统凭据及内存中的密钥引用，停止当前任务并回到未配置状态；保留本地历史 |
| 费用说明 | 检索使用你自己的 DeepSeek 账户额度，费用由 DeepSeek 收取；本产品第一期不提供支付、充值或订阅功能 |

保存时去掉首尾空白，拒绝空值及含内部空白或控制字符的输入；不假设密钥必须具备固定前缀或固定长度。取消或保存失败时保持原配置，不退回普通文件保存。保存失败提示“无法安全保存密钥，请重试”，保留本次输入供用户处理；关闭设置时清除未保存的密钥草稿。空输入不能代替删除操作。

“保存”只做本地格式基础检查，不发送任何网络请求，也不提示“鉴权成功”。搜索成功与余额查询成功分别记录连接状态，不用余额查询成功推断 Search / Fetch 可用。成功更换密钥时停止旧任务和余额请求，使旧响应失效，并清除旧密钥的连接状态及余额快照；新密钥保存后等待用户主动搜索或查看余额。首次提交搜索前展示一次服务说明并由用户确认启用：查询和待抓取网页地址会发送给 DeepSeek，费用由其 API 账户承担。更换密钥不反复展示同一份说明。

配置及搜索入口附近提示“请仅输入可发送至外部服务的内容”。首批内测使用公开资料；软件不自动判断内容是否保密。帮助中的控制台和文档链接须在发布前验证目标地址。

### 5.2 主窗口

窗口包含产品名、输入框、范围选择、搜索/停止按钮，以及历史和设置入口。初始说明为“复制一个技术点，查相关专利和技术资料”。

Windows 默认唤起快捷键为 `Ctrl+Alt+Space`，macOS 为 `Option+Command+Space`，均允许修改。注册失败时保留系统托盘或菜单栏入口，提示“无法注册快捷键，请检查系统设置或换一个组合”，不能静默覆盖系统或其他软件快捷键。用户主动点击唤起后，将焦点放入输入框；不得全局劫持普通输入。

快捷键在窗口隐藏时显示，在已显示且聚焦时收起。`Esc` 先关闭当前弹层，再关闭正文详情，最后收起主窗口。点击窗口外部不自动关闭；用户可切换到编辑器，搜索状态仍保留。

Windows 点击关闭按钮或按 `Alt+F4` 收起到系统托盘；macOS 点击红色关闭按钮或按 `Command+W` 收起窗口，菜单栏入口仍可用。首次收起时提示如何退出。Windows 托盘菜单、macOS 菜单栏菜单均提供“退出”；macOS 应用菜单“退出”及 `Command+Q` 真正结束应用。退出时取消全部未完成请求，包括余额查询。重新启动不自动恢复联网任务。

唤起和收起不读取剪贴板、不发送请求、不自动覆盖输入。粘贴、复制、全选和正文查找遵循系统习惯：Windows 使用 Ctrl，macOS 使用 Command。中文输入法与键盘导航需在两个系统分别验收。

### 5.3 输入与提交

输入支持中文、英文、数字、引号和关键词组合。界面显示字符计数。换行转换为空格并移除首尾空白，内部文字不自动改写；保存规范化后的内容作为本轮输入。

规范化后为空或超过 100 个 Unicode 字符时禁止提交，保留全部输入并就地解释，不自动截断。长度按 Unicode 码点计数，避免中英文或非 BMP 字符在不同端计数不一致。

首版输入定位为自然语言和关键词，不提供高级查询表达式编辑器。为防止与范围控制冲突，对独立操作符 `site:`、`-site:`、`lang:`、`before:`、`after:` 就地提示“请使用普通技术描述，并通过检索范围选择来源”，不发送该输入。引号和普通排除词可原样传入。

非输入法组词状态下按 Enter 提交；中文输入法确认候选词时不得提交搜索。输入错误不会清空上轮结果。

检索中修改输入只改变草稿，不改变在途任务。结果区域持续显示实际正在检索的词。提交新输入或新范围时取消旧任务并创建新任务；相同输入和范围在任务运行期间重复提交，不增加请求。任务结束后的再次提交明确视为重新搜索，可产生新费用。

### 5.4 结果与阅读

首个搜索响应返回有效结果后立即展示，不等待另一条查询或 Fetch 完成。首屏最多展示 5 条，少于 5 条按实际数量展示；不制造占位“推荐”资料。

| 卡片内容 | 展示规则 |
|---|---|
| 标题 | 来源返回的标题；为空时使用域名及 URL，不生成标题 |
| 来源 | 显示真实域名；可识别的 Google Patents 文档标为“专利页面”，其他结果标为“网页资料” |
| 公开号 | 仅在文档 URL 能可靠解析时展示，注明来自链接；无法识别时省略 |
| 检索摘要 | 优先使用 snippet，必要时展开 summary；始终标明“检索摘要” |
| 正文状态 | 未读取、读取中、已获取正文、正文不可用、读取已停止 |
| 原文预览 | 仅使用 Fetch 返回的真实正文，单独标明“抓取正文” |
| 操作 | 查看正文、打开来源、复制来源；无正文时不提供复制原文 |

不展示匹配百分比、侵权风险、授权概率，也不把 API 排序分数解释为技术相似度。搜索摘要即使包含看似直接引语的文字，也不能作为已核实原文展示。

正文详情显示抓取时间、来源链接、可选择文本和查找框。首版不承诺语义段落定位；只提供字面查找及命中高亮。打开详情时查找框为空，由用户输入关键词，不额外调用网络或模型。

正文预览取第一个非空正文段落的前 300 个 Unicode 字符，超出部分用 UI 省略提示表示；不拼接不连续句子，不称为“匹配证据”。详情保留完整已接收正文；如果因大小限制未完整接收，明确标示截断。

“复制来源”复制标题、公开号（若有）、URL。“复制选中原文”只在已选中抓取正文时可用，复制选中内容、来源 URL 和抓取时间；不虚构段落号或 PDF 页码。复制成功显示短暂反馈，不改变焦点中的用户输入。

“打开来源”在系统默认浏览器打开经过校验的原始 HTTP/HTTPS URL，不自动登录、绕过访问限制或承诺浏览器一定可以访问。外部网页能否打开单独于 Fetch 成功状态。

### 5.5 继续查找

- “修改检索词”：聚焦输入框，保留原词供用户编辑；不会假装自动生成同义词。
- 切换范围：只改变草稿选项，用户再次提交后才产生请求。
- “显示更多结果”：每次显示已接收候选中的下一组 5 条，不发新 Search，不自动读取新显示卡片的正文。
- 所有已接收候选显示完后提示“已显示本轮全部结果”，不提供无限滚动或虚假的下一页。
- 本轮没有更多结果时，用户可以修改检索词或范围，开始新一轮。

### 5.6 DeepSeek 账户余额

入口为“设置 → 检索服务 → 查看账户余额”。未配置密钥时提供填写入口，不发请求。入口旁说明“查询当前 API Key 所属的 DeepSeek 账户余额”。点击查看即使用已保存密钥向 DeepSeek 查询，不发送检索词、正文或本地历史，也不需要创建本产品账号。

| 展示项 | 规则 |
|---|---|
| 可用总余额 | 直接展示接口的 total_balance，包含赠金和充值余额，不与明细重复累加 |
| 余额明细 | 展示 granted_balance 为“赠金余额”、topped_up_balance 为“充值余额” |
| 币种 | 按 currency 分组显示，明确标注 CNY 或 USD；不合并不同币种，不做汇率换算 |
| 账户可用状态 | is_available 为 false 时提示“账户当前无可用余额”；为 true 只代表余额接口报告可用，不保证检索请求一定成功 |
| 更新时间 | 显示最近成功查询的本地时间；保留提示“余额可能因其他应用调用而变化，点击刷新查看” |
| 刷新 | 用户主动获取最新余额；请求中显示“正在查询余额”，按钮禁用且重复点击合并 |

首次点击“查看账户余额”且本次启动尚无成功快照时发起查询；已有快照时展示缓存和更新时间，点击“刷新”才再次请求。启动、保存密钥、唤起主窗口、打开设置或完成搜索都不自动查询余额，不做后台轮询。关闭余额面板不会重新发请求；已有请求可完成并更新本次会话的缓存。

余额请求单独管理，不占用单轮 Search / Fetch 的 14 次尝试预算。余额模块最多一个在途请求，单次超时 10 秒，不自动重试；与 Search / Fetch 的最多两个并发请求分别计数，因此应用最多同时存在三个 API 请求。余额查询或失败不阻塞搜索、正文阅读及取消操作。429 时遵守 Retry-After，倒计时结束后才允许手动刷新；没有该字段时默认等待 30 秒，不自动发出请求。

| 状态 | 界面与恢复动作 |
|---|---|
| 查询中且无快照 | 显示“正在查询余额”，金额位置不填 0 |
| 查询成功 | 展示余额、明细、可用状态和更新时间；真实零值按返回结果展示 |
| 网络失败或超时 | 无快照时显示“暂时无法查询余额，请重试”；有快照时保留旧值并标明“刷新失败，以下为上次查询结果” |
| 401 | 显示“API Key 无效，请在设置中更新”；旧快照不再作为当前余额展示，提供更换密钥入口 |
| 429、其他服务错误或响应不合规 | 显示对应查询失败状态，可用旧快照必须标明非最新；不把失败、空数组或缺失字段解释为零余额 |

金额以十进制字符串校验与保存，避免二进制浮点计算或展示造成精度变化；收到不支持的币种或无法解析的金额时标记响应不合规。余额是整个 DeepSeek 账户的快照，不是本产品专属额度，不用两次余额差值计算本次检索费用。余额为零或 is_available 为 false 时不直接禁止用户搜索，实际搜索响应决定是否停止本轮；避免旧余额阻止账户恢复后的正常使用。

更换或删除密钥时立即清空余额及时间，取消旧请求；迟到响应不得恢复旧账户余额。第一期仅查询和展示余额，不提供充值入口、支付流程、账单、消费流水、套餐或订阅。

## 6 检索与抓取规则

### 6.1 查询计划

设规范化后的输入为 Q。首版不自动拆技术特征、翻译、补同义词或改变用户的必要限定。

| 范围 | 查询计划 | UI 说明 |
|---|---|---|
| 专利与技术资料 | Q 加 `site:patents.google.com`；Q 原样通用网页查询；两条可并发 | 包含专利定向检索及通用网页检索，资料类型和完整性需核查 |
| 仅专利 | Q 加 `site:patents.google.com` | 当前定向来源为 Google Patents，不代表全量专利库 |

每条 Search 请求取 10 条结果，`need_content=false`；`ori_question` 使用 Q，不设置定位 IP。生成后的 query 必须再次检查官方长度限制。若内部生成不合法，阻止发送并记录可诊断错误，不静默丢词。

“仅专利”模式只展示识别为 Google Patents 专利文档路径的候选；站点主页、搜索列表等不混入正文结果。混合模式允许一般网页资料；通用检索中识别出的专利页同样可以展示。

### 6.2 合并与稳定展示

首个响应按其返回顺序建立卡片；之后的响应按返回顺序追加未出现的候选。不把不同查询的分数当作已校准分数做全局比较。用户正在查看的卡片不能因新响应到达而跳动、失焦或消失。

同一 Google Patents 公开号的不同语言页面合并，保留每个命中 URL 和查询来源，优先使用首次显示的 URL 抓取。文献种类代码属于身份的一部分，A1、B2 等不同版本不得合并，也不做专利同族合并。

其他网页按规范化 URL 去重：域名大小写及默认端口归一，忽略片段标识；保留路径及查询参数，不任意删除参数导致不同页面误合并。原始 URL 始终保留用于打开来源。无法确定是否相同的资料宁可分别显示。

### 6.3 正文获取

一轮任务建立结果后，自动读取最先展示的 3 个不同候选正文；结果不足 3 个按实际数量读取。用户点击其他候选“查看正文”时可以按需获取。两种方式共用本轮最多 5 个不同候选的抓取额度。

同一候选已有在途请求、成功正文或失败终态时，重复点击不重复发送。失败卡片保留打开来源入口；重新联网尝试通过整轮“重新搜索”进行，明确这是新一轮任务。当前版不在卡片内部提供无限重试。

达到本轮 5 个候选额度后，其他卡片提示“本轮正文读取次数已用完，可打开来源查看”，不自动扩大额度。显示更多结果不会增加额度。

Search 和 Fetch 共用最多 2 个并发网络请求；每个任务最多 2 次逻辑 Search 和 5 次逻辑 Fetch。已经返回的正文保持可阅读，不因其他页面失败而删除。

### 6.4 任务时限与请求预算

逻辑请求指一条计划查询或一个候选正文获取；网络尝试包含其重试。任何自动重试都计入网络尝试数。

| 参数 | 默认值 |
|---|---:|
| 单次网络尝试超时 | 15 秒 |
| 每逻辑请求自动重试 | 最多 1 次 |
| 单轮逻辑请求上限 | 2 Search + 5 Fetch |
| 单轮网络尝试上限 | 14 次，含重试 |
| 一轮任务允许发起新请求的时间窗口 | 从提交起 60 秒 |

达到 60 秒时取消未完成请求、清空队列，并保留已有内容。超时后仍未读取正文的卡片只能打开来源；重新获取需要开始新任务。前台 UI 不把一轮任务结束作为正文已经完整的证明。

默认退避 1 秒；若服务端提供 Retry-After，遵守其等待时间，且仅在本轮剩余时间足够完成重试时调度。无法等待到允许时间时结束该请求并提示稍后重新搜索，不提前发出重试。

按 2026-10-21 官方标价，混合模式 2 Search + 5 Fetch 全部有效成功、无重试的费用约为 0.035 元。14 次网络尝试均按单价估算为 0.07 元，但这只是调用预算估算，不是已核对账单。费用展示位于设置和本轮详情，不在搜索主流程反复弹窗。取消不能保证撤销已经到达服务端的处理或计费。

## 7 状态与中断行为

窗口可见性与检索生命周期分开管理。隐藏窗口只收起 UI，当前任务在原预算内继续运行，不发通知、不自动抢回焦点。

| 状态 | 用户看到什么 | 允许的操作 |
|---|---|---|
| 未配置 | 用途、示例、配置入口 | 编辑输入、配置服务 |
| 待检索 | 输入及范围 | 搜索、查看历史 |
| 检索中 | 实际查询词、文字进度、停止按钮 | 编辑草稿、停止、提交新任务 |
| 结果可读 | 已返回卡片，部分正文陆续更新 | 打开来源、阅读、复制、修改输入 |
| 本轮完成 | 已有结果及本轮范围 | 查看已有内容、显示更多、重新搜索；60 秒窗口内可按预算按需 Fetch |
| 部分失败 | 已有结果及受影响来源/正文的简短提示 | 继续用已有结果或重新搜索 |
| 无结果 | 所有 Search 正常完成但没有可显示候选 | 改词、改范围、重新搜索 |
| 失败 | 没有可用结果且请求失败 | 按错误提示修复或重新搜索 |
| 已停止 | 已返回内容保持，未完成项标为停止 | 查看已有内容或重新搜索 |

“本轮完成”表示当前队列已完成；在时限和额度内按需 Fetch 会重新进入“结果可读”。时限截止后仅提供已有内容和打开来源，历史恢复不会重新开放已结束任务的额度。

每次提交产生新的 run_id。取消、替换任务、删除历史或退出后，旧响应即使到达也不得更新新结果、写回已删除历史或触发后续抓取。点击停止立即禁止新请求和重试；尝试取消在途请求，但不等待其返回才响应 UI。

任务进行中网络断开，显示已有结果；自动重试结束后进入部分失败或失败。网络恢复不在后台自行重启任务。用户主动重新搜索才开始新一轮。

## 8 异常与界面文案

| 情况 | 用户文案 | 行为 |
|---|---|---|
| 空输入 | 请输入一个技术点或公开号 | 不发请求 |
| 输入过长 | 最多输入 100 个字符，请缩短描述 | 保留输入，不截断 |
| 未配置 | 配置 DeepSeek API Key 后即可搜索 | 打开设置 |
| 401 | 检索服务密钥无效，请在设置中更新 | 不重试，停止本轮剩余联网操作 |
| 402 | DeepSeek 账户余额不足，可查看账户余额 | 不重试，停止本轮剩余检索操作；提供余额面板入口，用户点击后才查询 |
| 429 | 检索服务繁忙，正在稍后重试 | 按退避和时间预算处理；结束后允许主动重新搜索 |
| 网络或服务暂时失败 | 暂时无法完成检索，已保留返回的结果 | 有限重试，结束后保留数据 |
| 单个 Fetch 被拒绝或不可用 | 无法读取此页正文，可以打开来源查看 | 不影响其他候选；不自动绕过限制 |
| Fetch 200 但正文为空 | 此页未返回可读正文 | 不标为已获取正文，不显示虚假原文 |
| 混合模式部分 Search 失败 | 部分来源未完成，以下为已返回结果 | 不显示成完整范围检索成功 |
| 全部 Search 成功但无候选 | 本轮未找到相关资料，试试修改关键词或扩大范围 | 不表示相关技术不存在 |
| 用户停止 | 已停止，已返回的结果仍可查看 | 停止后续任务 |
| 总时限到达 | 本轮已结束，已保留返回的结果 | 停止后续任务，允许重新搜索 |

对于其他不可重试请求错误、协议不符及本地失败，主界面提供简短说明和可恢复动作；诊断页记录错误类别、状态码及请求时间，不直接展示可能包含密钥或查询内容的服务端原始错误。

## 9 结果真实性与内容处理

Search 的 snippet、summary 是检索服务返回的摘要，不当作正文引文。Fetch 返回内容标为“抓取正文”，表示来自该次网页获取，不表示它与专利官方文件一致、完整或具有已核实的公开日期。

首版不在卡片显示推断的申请人、法律状态、优先权日或公开日。API 的 date 若保留在详情中，只能标为“服务返回的网页日期，未经核实”；缺失时不补猜测值。

正文作为不可信内容渲染：禁止执行脚本或页面指令，禁止自动加载远程图片、iframe、附件及追踪资源。Markdown 链接只在用户点击后校验并交给浏览器；不接受可执行或本地文件协议。文中的指令不能改变应用设置、请求计划或数据导出行为。

单响应读取上限为 5 MiB，正文展示上限为 200,000 个 Unicode 字符。触及读取上限或无法解析时显示正文不可用；可以解析且仅触及展示上限时保留前部正文并标为“正文显示不完整，请打开来源”。复制只能包含实际显示、可核对的文本。遇到不支持的图片或公式，不推断其内容。

## 10 本地数据与设置

API Key 通过 Rust 后端保存至 Windows Credential Manager 或 macOS Keychain；不写入 WebView 的 localStorage、普通配置文件、日志、历史、错误报告或安装包。前端仅在输入新密钥时短暂持有草稿，保存后清除，不提供读取完整已保存密钥的命令。删除密钥立即阻止新请求，停止当前任务并清空余额；已有本地检索结果仍能查看。客户端固定访问官方 API，不提供把用户密钥发送到任意自定义网关的设置。

账户余额快照仅存本次运行的内存，退出、更换或删除密钥时清除，不进入检索历史、日志或指标导出。余额请求使用内部凭据版本号关联当前配置，不以明文密钥或密钥哈希作为日志中的账户标识。

查询历史默认开启，首次服务说明中写明只保存在当前设备，可关闭。保留最近 50 个任务且最长 30 天，两者取更严格的限制；应用启动和保存时清理过期数据。历史关闭后不持久化新查询及其内容，但当前窗口仍可在内存中使用。

历史项保存查询、范围、时间、结果摘要、来源、已显示原文预览和任务终态。完整抓取正文仅作本地缓存，最长 24 小时、总计最多 50 MiB，超限按最早使用记录清理。缓存被清理不影响历史摘要，详情明确显示“正文缓存已清理”，提供打开来源或重新搜索。

打开历史不自动联网，不把旧结果标为最新结果。点击“重新搜索”产生新 run_id 并重新计算本轮预算。关闭应用前将运行中任务记为已停止；重新打开不自动续跑。

删除单条历史同时删除该任务的正文缓存及预览；删除当前运行任务时先停止并使后续响应失效。清空历史清除全部查询和内容缓存。清空操作可以要求一次确认并说明范围，但日常搜索不反复要求确认。

本地设置包括：API Key 管理、账户余额查看与刷新、全局快捷键、是否保存历史、清空历史、查看服务说明、导出内测指标。默认不开机启动；如以后提供该选项必须由用户主动开启。

## 11 数据对象与事件约定

字段名称用于前后端及持久化对齐，不限定实现语言。结构应带 schema_version，避免升级后误读旧数据。

| 对象 | 最小字段与约束 |
|---|---|
| SearchRun | run_id、schema_version、query、scope、created_at、deadline_at、status、cancelled_at、请求预算、来源级错误、结果 ID 列表 |
| SearchHit | result_id、run_id、original_url、canonical_key、title、source_domain、source_type、snippet、summary、retrieved_at、命中查询及其序位；API 分数仅内部保留 |
| PatentIdentity | publication_number_candidate、identity_source=url；不可识别时为空，不从正文引用中的其他号码推断本篇身份 |
| PageContent | result_id、fetch_status、fetched_at、title、content、content_hash、truncated、error_kind；状态与数据相符 |
| RequestAttempt | run_id、操作类型、逻辑请求 ID、attempt_index、开始/结束时间、HTTP 状态或网络错误、cancelled；不得存密钥 |
| AppSettings | schema_version、credential_reference、hotkey、history_enabled、service_notice_accepted；密钥本身不在此对象 |
| BalanceSnapshot | credential_generation、request_id、fetched_at、is_available、balance_infos；每项保留 currency 及三种余额的十进制字符串，仅内存保存 |
| BalanceViewState | unconfigured、idle、loading、available、stale、error；另存错误类别和允许再次刷新时间，旧快照与当前状态分开管理 |

PageContent 的状态限定为 not_requested、queued、loading、available、empty、failed、cancelled。Fetch 成功且正文非空才可标为 available；不以 HTTP 200 单独判定成功。

事件至少覆盖：run_started、search_batch_received、fetch_started、fetch_completed、result_opened、source_opened、source_copied、query_edited、run_cancelled、run_finished。所有异步内容事件必须携带 run_id 和 result_id（若适用），在写入前校验任务仍有效。

余额事件独立于检索 run_id，携带 request_id 和 credential_generation。写入状态前同时校验请求仍有效且凭据版本一致；余额成功不触发 Search / Fetch，不改变检索任务状态。Tauri 前端仅调用必要的后端命令，Rust 后端处理凭据、固定目标地址的网络请求和响应校验，再返回可展示字段；远程正文不能访问这些命令。

## 12 API 对接约束

接口事实以官方文档为准，以下是在 2026-10-21 核对的最小契约；产品参数通常比官方上限更保守。

| 接口 | 请求与响应要点 |
|---|---|
| `POST https://api.deepseek.com/v1/tools/search` | query 为 1～128 个 Unicode 字符；count 为 1～50；支持 ori_question、need_content；响应含 results 数组及标题、URL、摘要等字段 |
| `POST https://api.deepseek.com/v1/tools/fetch` | url 为带 host、无用户名密码的 HTTP/HTTPS 地址，最长 8192 字符；响应含 title 和 Markdown content |
| `GET https://api.deepseek.com/user/balance` | 使用同一 API Key，无请求体；响应为 is_available 布尔值及 balance_infos 数组，数组项含 currency、total_balance、granted_balance、topped_up_balance；三种金额均为字符串 |

使用 Bearer 鉴权并解析 JSON 响应。Search / Fetch 对 408、429、5xx 和暂时网络错误按本产品预算重试；其他 4xx 不自动重试。Search / Fetch 收到 401、402 时停止本轮检索调度并取消当前检索队列；取消完成前已返回的合法结果可以保留。余额接口按 5.6 节执行，不自动重试，失败只更新余额面板；更换或删除密钥则统一取消两类任务。

无效 URL、不合规协议和缺失必要字段的结果不应进入可点击列表。单个结果项损坏可以跳过并记录条目错误；若响应整体结构无法解析，则标记该来源失败，不能伪装为空结果。

官方参考：[Search](https://api-docs.deepseek.com/zh-cn/api/search/)、[Fetch](https://api-docs.deepseek.com/zh-cn/api/fetch/)、[使用指南及费用](https://api-docs.deepseek.com/zh-cn/guides/search/)。未列出的分页、深度检索和专业字段能力不假定存在。

余额字段及币种依据 [DeepSeek 查询余额文档](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/)。刷新时机、超时和缓存策略属于本产品设计，不是官方接口保证。

## 13 性能与使用质量

Windows 与 macOS 分别验收、分别记录结果，不能用单平台通过替代双平台交付。参考设备：Windows 11 x64、4 核 CPU、8 GiB RAM、SSD；macOS 13 及以上的 Apple Silicon 和 Intel 设备、8 GiB RAM、SSD。记录实际芯片、系统版本、构建架构和网络条件。界面本地响应与外部 API 延迟分别统计。

| 指标 | 目标及测量方式 |
|---|---|
| 热唤起 | 按快捷键到输入框可输入，P95 ≤300 毫秒 |
| 提交反馈 | 用户提交到显示检索中，≤100 毫秒 |
| 首批卡片 | 收到有效 Search 响应到卡片可交互，≤200 毫秒 |
| 停止反馈 | 点击停止到 UI 确认并停止调度，≤100 毫秒 |
| 首批真实资料 | 提交到第一条真实来源可点击，内测目标 P50 ≤5 秒、P95 ≤12 秒；不达标需先定位 API/客户端耗时 |
| 正文增强 | 首批资料可用不依赖 Fetch 完成；Fetch 慢或失败不阻塞打开来源 |
| 视觉可用性 | Windows 在 1366×768、100% 和 150% 缩放下验收；macOS 在默认及缩放显示模式下验收；主操作可见，详情可滚动，窗口不超出可用屏幕 |
| 键盘操作 | 输入、提交、停止、选择结果、打开来源、返回均可通过键盘完成，焦点可见且不被异步更新抢走 |
| 余额操作 | 打开面板和点击刷新在 100 毫秒内反馈；查询在 10 秒内返回或进入超时状态，不冻结输入和检索结果 |

界面延迟至少执行 100 次操作测量；真实接口指标至少记录 30 次公开主题查询，失败和超时计入统计并单列，不只挑成功请求。性能不满足时可以进入问题修复，不以静态假数据代替真实结果通过验收。

## 14 内测指标与验证条件

产品首要验证“用户是否在实际工作中反复主动调用”。初期测试用户不少于 5 人，尽可能包含两类角色，并记录其使用许可与环境。只用公开、允许用于外部检索的任务。

指标默认仅本地统计，不自动上传。用户主动导出的指标包含随机任务 ID、时间、行为计数、耗时、状态和调用次数，不包含查询原文、URL、标题、正文、账户余额、密钥或其可逆标识。用户角色由访谈记录，避免在产品里强制收集身份。

| 指标 | 定义 |
|---|---|
| 活跃使用日 | 当日至少提交一次有效查询，并执行打开来源、展开正文或复制来源中的任一动作 |
| 重复使用 | 同一用户在多个工作日主动使用；另记录每活跃日不同查询的数量，重复重试不计作不同查询 |
| 有用结果 | 用户人工评价至少一条资料值得进一步阅读；点击仅作为行为代理，不能等同于相关 |
| 任务时间 | 从准备搜索到找到用户认可的资料，与其现有方式用难度相近任务对比 |
| Fetch 增量 | 用户是否通过正文预览减少无效网页打开，或更快判断资料是否值得阅读 |
| 单任务成本 | 实际网络尝试、有效返回及成本估算，与用户认可的任务结果一并记录 |

建议继续产品化的条件：五位用户中至少三位在一周内主动使用三天以上；第二周仍有至少三位返回；至少 30 个公开任务中，70% 的任务有一条被评为值得进一步阅读的结果；任务完成时间中位数比现有流程降低 30%。这些是内测决策门槛，不代表召回率或市场证明。

另做 Search-only 与 Search+Fetch 对比，确认正文读取是否产生实际价值。若用户只用打开链接，先减少自动 Fetch 成本，再重新判断 Fetch 的产品作用；不得仅为使用接口而强迫用户等待正文。

第一期只验证重复使用、检索质量和实际省时，不开发收费页面、套餐、订阅、充值、订单、收银台或试用到期限制，也不以购买产品额度解锁功能。后续商业化另行定义需求。若未形成重复使用，不以增加案件管理、撰写等功能掩盖检索主流程的问题。

## 15 开发顺序与发布条件

| 阶段 | 交付内容 | 完成条件 |
|---|---|---|
| M0 接口验证 | 使用公开主题执行 Search / Fetch，核对余额契约，记录耗时、错误和预算，不记录密钥或余额数值 | 三个真实接口均有验证记录；Google Patents 抓取效果及一般网页来源情况有记录 |
| M1 桌面闭环 | Tauri 双平台窗口、配置、唤起、输入、渐进结果、打开来源、余额查看与刷新 | Windows 和 macOS 均可不用命令行完成检索及余额查询 |
| M2 正文与稳定性 | 自动/按需 Fetch、正文阅读、取消、任务隔离、异常、预算 | 关键异常及竞态验收通过，不出现错配数据或超预算调度 |

发布前必须满足：无内置共享密钥；正文与摘要标识正确；失败不生成假结果；取消与新旧任务隔离可靠；使用范围、费用和数据去向可理解；安装包在目标系统可安装、启动和卸载。常规安装包的签名及系统提示处理应在分发前完成技术方案，不能指导用户关闭系统防护才能运行。
